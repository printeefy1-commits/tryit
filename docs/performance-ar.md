# تحسين تحميل المتجر والمرآة — 31 أكتوبر 2026

طُبّقت إرشادات التحميل المؤجل والكاش من مهارتي ECC [frontend-patterns](https://github.com/affaan-m/ECC/blob/main/skills/frontend-patterns/SKILL.md) و[backend-patterns](https://github.com/affaan-m/ECC/blob/main/skills/backend-patterns/SKILL.md) بعد فحص الإصدار `bb1545e`.

## التنفيذ

- أصبح `public/app.js` متجرًا خفيفًا، ويُستورد `tryon.js` عند اختيار تجربة نظارة. لا يُطلب Three.js أو MediaPipe أو GLB أو WASM أثناء تصفح المتجر فقط.
- يطلب `camera-request.js` إذن الكاميرا ضمن النقرة الأصلية، بالتوازي مع تنزيل المحرك. تُوقف النتيجة المتأخرة إذا أُغلقت النافذة أثناء التحميل. عند تعذر تحميل نسخة قديمة بعد نشر تحديث، يقترح الزر تحديث الصفحة بدل تكرار طلب ملف قديم.
- يقدّم `static-assets.js` ملفات JavaScript/CSS/WASM/التتبع بنسخ Brotli/gzip دون فقد، محفوظة على القرص حسب بصمة المحتوى. أول طلب يولّد النسخة مرة واحدة في طابور متسلسل؛ ثم تُعاد قراءتها من الكاش.
- تحمل مسارات `/assets-v/<build>/...` بصمة إصدار ومحتوى وتتلقى كاش سنة `immutable`. تحفظ الخدمة نسخة مطابقة للملف حتى لو تغيّر المشروع على القرص أثناء تحديث Git/npm. تبقى المسارات القديمة قابلة لإعادة التحقق ومضغوطة. ملفات HTML وواجهات الإدارة والجلسات تحتفظ بـ`no-store`، ويوافق هاش CSP خريطة imports المولّدة.
- تستخدم CSS وخانة preload رابط الخط نفسه لتجنب تنزيله مرتين. أضيف شعار WebP بحجم نحو22 KB وأيقونة صغيرة بدل استعمال PNG بحجم116 KB في الموضعين.
- ينشئ `product-image-variants.js` صور WebP بعروض128/800/1600 مع الحفاظ على نسبة الأبعاد ودون تكبير صورة صغيرة، وبحد ارتفاع ضعف العرض. يستفيد الرفع القديم والجديد تلقائيًا من `/product-images/v1/<size>?src=...` دون تغيير الكتالوج أو الأصل. تُحمى قراءة المصدر بالامتدادات والمسارات وrealpath، وتُحد أبعاد الإدخال وطوابير المعالجة. تُشارك الطلبات المتزامنة للعمل نفسه.
- يُستخدم128 للمصغرات، و800/1600 للبطاقات والصورة الرئيسية بحسب كثافة الشاشة. يعود المتصفح إلى الصورة الأصلية إذا تعذر إنشاء المشتقة.
- يعاد استخدام متجهات وأشعة الحجب، وتُعاد حدود أقنعة العمق عند تغير بياناتها فقط. تحقق فحص ست وضعيات للمجسم من مطابقة حدود الحجب وأعداد المثلثات للنسخة السابقة. لا يُنسب تحسن كبير في FPS إلى هذا التغيير الصغير.

## القياس قبل وبعد

استُخدم Chromium بعرض390×844 وكثافة2، ومحاكاة تنزيل1.6 Mbps و150 ms تأخير وCPU أبطأ4 مرات. الأرقام وسطاء دورتين باردتين للمتصفح، على خادم محلي معزول دون Nginx وبمنتجي الاختبار نفسيهما. كاش المشتقات على الخادم كان دافئًا في دورات المحاكاة البطيئة؛ قد تضيف أول زيارة بعد النشر وقت توليد قصيرًا. هذه ليست قياسات EC2 المنشور أو هاتف المالك.

| القياس | قبل | بعد |
|---|---:|---:|
| نقل تحميل المتجر الأول | 2,850,971 بايت | نحو240,600 بايت |
| استجابات تحميل المتجر | 29 | 11 |
| ظهور أكبر عنصر مرئي LCP | 15.03 ثانية | 1.73 ثانية |
| ملف WASM، مع Brotli | 11,153,617 بايت دون ضغط | 2,692,161 بايت |

انخفض نقل صفحة البداية بنحو **91.6%**. بيانات WASM قبل التحسين مؤكدة من استجابة خادم الإنتاج التي أرسلها المالك؛ رقم Brotli هو حجم الملف نفسه دون تغيير المحتوى، وتحقق محليًا من فك الضغط إلى البايتات الأصلية.

عينة صورة HEIC محوّلة من مسار الرفع الحالي: JPEG بأبعاد3024×4032 وحجم2,169,061 بايت. المشتقات:128×171 بحجم2,164 بايت؛800×1067 بحجم24,630 بايت؛1600×2133 بحجم314,730 بايت. حجم الملف ومدى تقليله يعتمدان على محتوى الصورة. الصور المعاد ترميزها تُراجع بصريًا؛ ضغط WASM/JS نفسه دون فقد.

## التحقق

- اجتازت اختبارات Node الـ79، بما فيها فك الضغط المطابق، وHEAD/Range/304، وعزل المسارات، وتغيير إصدارات الأصول، وثبات هاش CSP، وصور المنتجات، والذراع الأصلية وخيار+20%.
- اجتاز `test:performance` حد500 KB لموارد المتجر التجريبية، وغياب محرك المرآة قبل النقر، وطلب الكاميرا داخل النقرة، وإغلاقها قبل اكتمال تحميل الوحدة، ثم إعادة فتحها.
- اجتازت اختبارات المتصفح والإدارة، ورفع GLB والصور، وفتح المرآة بخيار+20%، وإلغاء الإطالة دون إعادة رفع GLB.
- اجتازت اختبارات الهاتف: المنظور الكامل والخلفية المموهة، وأدنى زوم مدعوم، وتدوير الشاشة، والتبديل بين النظارات، ورفض الإذن والنتيجة المتأخرة.
- اجتاز اختبار الإطار المتزامن ربط صورة الكاميرا والنظارة بالإطار نفسه، وفقد التتبع المؤقت ثم التعافي. واختبار التنزيل البطيء/404 والإلغاء وإعادة المحاولة.

أمثلة إعادة التحقق:

```bash
npm test
npm run test:browser
CAMERA_FIXTURE=/path/to/face.y4m npm run test:performance
CAMERA_FIXTURE=/path/to/face.y4m node scripts/mobile-camera-smoke.mjs
CAMERA_FIXTURE=/path/to/face.y4m node scripts/admin-upload-smoke.mjs
```

## النشر والكاش

لا توجد اعتماديات جديدة. يحتاج هذا التحديث سحب Git وإعادة تشغيل `tryit`. تُنشأ النسخ المضغوطة ومقاسات الصور تلقائيًا، ولا يحتاج المالك إلى إعادة رفع الصور أو GLB. لا يعتمد ضغط النقل على تثبيت وحدة Brotli في Nginx؛ تقدمه الخدمة نفسها.

الكاش القابل لإعادة الإنشاء: `data/static-cache` (نحو72 MB أول مرة بحسب النسخ المثبتة) و`data/image-cache-v1`. لا حاجة لنسخه احتياطيًا؛ سكربت النسخ الاحتياطي الذي يجمع الكتالوج والملفات المشار إليها فقط يستبعده أصلًا. قد يحتاج تبويب مفتوح من قبل التحديث إلى تحديث الصفحة عند طلب وحدة مؤجلة من إصدار قديم.

للتحقق على EC2 بعد النشر، ينبغي أن يظهر `Content-Encoding: br` أو `gzip` وحجم أصغر؛ الرابط القديم يظل يعيد التحقق، بينما يستعمل المتصفح الروابط ذات الإصدار للكاش الطويل:

```bash
curl -sS -D - -o /dev/null -H 'Accept-Encoding: br, gzip' \
  https://16.192.70.157.sslip.io/vendor/vision/wasm/vision_wasm_internal.wasm
```

ما زال استدلال الوجه الحالي يعمل بـCPU؛ نقل التتبع إلى Worker أو اختيار GPU يتطلب قياسًا على أجهزة فعلية واختبارات تزامن إضافية. يركز هذا التحديث على التحميل والصور والكاش وتقليل العمل المتكرر في الحجب.
