# إضافة المنتجات والصور وملفات GLB مباشرة

لوحة الإدارة: `https://16.192.70.157.sslip.io/admin.html`. تستعمل كلمة مرور المدير الموجودة على الخادم. بعد تهيئة الإصدار مرة واحدة، لا تتطلب المنتجات الجديدة GitHub أو الطرفية أو إعادة تشغيل الخدمة.

## الاستعمال

1. سجّل الدخول واضغط «Ajouter une monture».
2. اكتب اسم الموديل والعلامة، واختر حتى 10 صور دفعة واحدة وملف GLB، أو اسحب الملفات إلى خانتي الرفع.
3. اختر الصورة الرئيسية بواسطة «Définir principale». يمكن إزالة صورة من الاختيار أو معاينة الصور المصغّرة قبل الحفظ. راجع المعاينة ثلاثية الأبعاد. تتاح «Face» و«3/4» والسحب للتدوير. صحّح اتجاه الموديل عند الحاجة، وأدخل عرض الإطار الحقيقي بالملليمتر إن توفر. باقي ضبط الحجم والارتفاع اختياري.
4. اترك «Visible dans la boutique» مفعّلًا للنشر، أو ألغِه لحفظ المنتج دون عرضه.
5. اضغط «Enregistrer» وانتظر التأكيد. تعرض اللوحة تقدّم الإرسال ثم تحسين الموديل والتحقق والحفظ. قد تستغرق المعالجة بضع دقائق؛ لا يلزم إبقاء المتجر في انتظار تحميل الأصل الكبير. يظهر المنتج المنشور في المتجر، ويظهر GLB في شريط الموديلات داخل الكاميرا.

لتحديث منتج، اضغط «Modifier». ترك خانة ملف فارغة يحافظ على الملف الحالي. البحث وحالات الإظهار ووجود GLB متاحة في القائمة. يمكن حفظ منتج دون GLB؛ يظهر في المتجر لكنه لا يُتاح للتجربة حتى إضافة المجسم.

## الملفات والملاءمة

- GLB ذاتي الاكتفاء حتى **100 MiB**، بصور خامات مدمجة. لا تُقبل موارد خارجية. تُحمّل ملفات Draco وMeshopt المتوافقة من مكتبات الموقع نفسه؛ خامات KTX2 غير مدعومة، ويجب تصديرها PNG/JPEG/WebP.
- حتى **10 صور JPG/PNG/WebP/HEIC/HEIF** للمنتج، بحد **10 MiB لكل صورة**. تُحفظ الصورة الرئيسية في `image` والمجموعة المرتبة في `images`، وتُعرض الصور الأخرى للعميل بأزرار مصغّرة داخل بطاقة المنتج. يحوّل الخادم HEIC إلى JPG. إذا لم يدعم المتصفح عرض HEIC، يظهر توضيح بدل المعاينة حتى الحفظ؛ تظهر الصورة المحوّلة بعد ذلك في القائمة.
- يحتفظ الرفع بالأصل ويُعد نسخة ويب تلقائيًا، بضغط Meshopt وتحسين الخامات وتبسيط محافظ للهندسة الكثيفة. [سياسة الجودة وأحجام الاختبار](model-optimization-ar.md). ملف خفيف ومفتوح الأذرع وموجّه للأمام يعطي تجربة أسرع وأفضل على الهاتف. حجم 100 MiB حد استقبال وليس توصية لحجم كل موديل.
- يُحسب موضع تثبيت تقريبي من مقدمة الموديل. إعداد الاتجاه واحد في المعاينة والكاميرا. تحتفظ الموديلات المعروفة ذات البيانات المضمّنة بمعايرتها السابقة. لا يُعتبر ذلك قياسًا فعليًا للوجه أو ضمانًا لملاءمة النظارة.
- ملفات المنتج ومقاسه وظهوره تبقى عند التعديل. تحفظ مسارات الملفات السابقة عند استبدالها، ولا تُحذف الملفات القديمة تلقائيًا. محاولات إعادة الإرسال من النموذج نفسه تستخدم معرّف المنتج نفسه لتجنب إنشاء نسخ مكررة.

## تهيئة واحدة على EC2

اسحب الإصدار وانتظر نجاح النسخة الاحتياطية:

```bash
cd ~/tryit
git pull --ff-only origin main
sudo install -m 0644 scripts/backup.py /usr/local/lib/tryit-backup.py
sudo systemctl start tryit-backup.service
```

ثم ثبّت اعتماد تحويل HEIC وتحسين GLB ووسّع حد Nginx:

```bash
sudo systemctl stop tryit
npm ci --omit=dev
sudo python3 scripts/configure-admin-uploads.py
sudo systemctl start tryit
```

أعد تشغيل `tryit` إذا فشل التثبيت، وراجع الخطأ قبل محاولة الرفع. لا تحتاج لتغيير كلمة المرور أو إعدادات AWS أو الشهادة. يُحدّث سكربت Nginx الموقع `/etc/nginx/sites-available/tryit-elastic` فقط، ويحفظ نسخة منه، ويترك TLS والتوجيه كما هما. يضبط الطلب على 220 MiB ليتسع لملف GLB وعشر صور وتغليف الطلب، ويتحقق بواسطة `nginx -t` قبل إعادة التحميل. عند فشل التحقق يعيد ملف الإعداد السابق. يمكن مراجعة التغيير قبل تطبيقه باستخدام `--dry-run`.

هذه الأوامر مطلوبة لتحديث التطبيق مرة واحدة. بعد ذلك، تضاف المنتجات والصور والمجسّمات من لوحة الإدارة فقط.

## التخزين والفحص

- تُكتب الملفات الواردة في `data/incoming` غير المتاح للويب، وتُفحص بنية GLB وحجمه وموارده قبل النشر. تنقل الملفات المقبولة إلى `uploads` بأسماء عشوائية، ثم يحدّث الكتالوج ذريًا. تنظّف الملفات المؤقتة عند انتهاء الطلب أو انقطاعه.
- صلاحيات الجلسة والأصل مطلوبة قبل استلام الملفات. الطلبات غير المصرّح بها لا تنشئ منتجات أو ملفات منشورة. تعرض الواجهة أخطاء الحجم والصيغة وانتهاء الجلسة والاتصال.
- تبقى `data/catalog.json` و`uploads` خارج Git، ويشمل سكربت النسخ الاحتياطي المحدّث الصورة الرئيسية وجميع صور المجموعة وأصل GLB ونسخته المحسّنة وملفات النقل المضغوطة المشار إليها في الكتالوج. يجب تحديث نسخة السكربت المثبتة في `/usr/local/lib/tryit-backup.py` بالأمر المذكور أعلاه. لا يُثبّت Blender أو أدوات معالجة GPU على EC2.

## التحقق

```bash
npm test
npm run test:browser
CAMERA_FIXTURE=/path/to/face.y4m HEIC_FIXTURE=/path/to/photo.HEIC node scripts/admin-upload-smoke.mjs
CAMERA_FIXTURE=/path/to/face.y4m TRYON_PRODUCT_ID=head-12028-models-v2 MODEL_SWITCH=1 node scripts/camera-smoke.mjs
CAMERA_FIXTURE=/path/to/face.y4m TRYON_PRODUCT_ID=head-12028-models-v2 node scripts/mobile-camera-smoke.mjs
```

يتحقق الاختبار الكامل من رفع عدة صور، منها HEIC، واختيار صورة رئيسية، وGLB حجمه أكبر من 25 MiB، ومعاينة المجسم وتغيير اتجاهه، وإظهار تقدّم الإرسال، وحفظ المقاس والضبط، وإعادة فتحه للتعديل، ثم نشر مجموعة الصور والتبديل بينها وظهوره في شريط الموديلات ونجاح تتبع الوجه بالكاميرا. يستخدم GLB ببيانات هندسية فعلية وحشو BIN غير مستخدم لاختبار حد الحجم دون إرهاق مصيّر Chromium البرمجي بملايين المثلثات. اختُبر تحويل إحدى صور المالك فعلًا؛ لا تُضمّن الصور الخاصة أو فيديو الاختبار في Git.

تفحص اختبارات API استبدال GLB مع الاحتفاظ بالقديم، وعدم تكرار المنتج عند إعادة الإرسال، ورفض الصيغ غير الصالحة والموارد الخارجية دون تغيير الكتالوج. تفحص اختبارات إعداد Nginx المحافظة على TLS والتوجيه وقابلية إعادة التشغيل. هذه فحوص محلية؛ النشر الفعلي وإعداد Nginx على EC2 يتطلبان الأوامر أعلاه.

## تصحيح معاينة GLB كثيف الهندسة

أُعيد إنتاج `Maximum call stack size exceeded` في تجميع مؤشرات العدسات، حيث كان `push(...lenses)` يمرر مئات آلاف المعاملات دفعة واحدة. أصبحت المؤشرات تُجمع في مصفوفة مهيّأة مسبقًا، مع بحث ثنائي لقصّ الأذرع عند الحجب. لا تُحذف المثلثات ولا تتغير الألوان أو الخامات. اختُبر الملف الأصلي بحجم 62.7 MiB و1.5 مليون مثلث داخل معاينة الإدارة، إلى جانب اختبار انحدار بمئات آلاف مؤشرات العدسات.

```bash
LARGE_GLB_FIXTURE=/path/to/original.glb node scripts/large-model-smoke.mjs
python3 test/test_backup.py
```

هذا التصحيح لا يبسط الموديل تلقائيًا؛ يبقى الملف الخفيف أسرع للكاميرا على الهاتف. رسالة HEIC في المعاينة قبل الحفظ توضيح لعدم دعم بعض المتصفحات عرض الصيغة، وليست فشلًا في الرفع؛ تُحوّل الصورة على الخادم عند الحفظ.
