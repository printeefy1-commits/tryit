# تحسين GLB تلقائيًا للتحميل على الهاتف

بعد تثبيت هذا الإصدار، ارفع GLB الأصلي مرة واحدة من لوحة الإدارة. أثناء الحفظ تظهر «Optimisation du modèle 3D…». يحتفظ الموقع بالملف الأصلي دون تغيير، وينشر رابطًا جديدًا لنسخة الويب. المتجر لا يحمّل الأصل ولا الموديلات الأخرى مقدمًا؛ يحمّل الموديل المختار للتجربة فقط.

## السلوك

- تظهر أحجام النسخة والأصل ونسبة التوفير في الإدارة. عند تعديل المنتج يوجد رابط «Télécharger le GLB original»؛ معاينة المنتج المحفوظ تستخدم نسخة الويب الفعلية.
- في الإنتاج (`NODE_ENV=production`) تُعالج الموديلات الموجودة بالتتابع في الخلفية عند تشغيل الإصدار لأول مرة. يستمر تقديم الملف السابق حتى تنجح المعالجة. تحفظ الصور والمقاسات والاتجاهات والتسمية والظهور وضبط الملاءمة. لا تتكرر المعالجة عند إعادة التشغيل لنفس إصدار الخوارزمية.
- يمكن بدء المعالجة أو إعادة محاولة موديل قديم بواسطة «Alléger le GLB». لا تحتاج لإعادة رفعه. إذا تغير ملف المنتج أو حُذف خلال المعالجة، لا يستبدل الناتج التعديل الأحدث.
- إذا فشلت المعالجة، يبقى الكتالوج والموديل الحالي كما هما. لا تُنشر ملفات جزئية. إذا كانت النسخة الناتجة أكبر، يُستخدم محتوى الأصل نفسه وتظهر «Déjà compact».
- الملفات تحت `uploads/` لها أسماء جديدة عند كل استبدال، مع `Cache-Control: public, max-age=31536000, immutable`. يتفاوض الخادم على Brotli أو gzip عند توفر نسخة أصغر، ويقدم GLB عاديًا لبقية المتصفحات. يوضح `X-Model-Bytes` الحجم بعد فك الضغط كي لا تتجاوز نسبة التنزيل 100%.

## سياسة الجودة

1. دمج الرؤوس المتطابقة تمامًا وترتيب البيانات، ثم ضغط Meshopt. لا نكمّم إحداثيات المواضع ولا النورمال ولا UV؛ تظل كاملة الدقة، وتبقى التحويلات والخامات وأسماء أجزاء النظارة وبيانات نقاط التثبيت محفوظة. يتوافق ذلك مع تحريك الأذرع داخل محرك التجربة.
2. للمجسمات الثابتة التي تزيد على 100 ألف مثلث: هدف 100 ألف، مع قفل حدود الهندسة وحد خطأ هندسي **0.1% من نصف قطر الجزء**. قد يتوقف التبسيط فوق الهدف لحماية الشكل. لا تُبسّط المجسمات ذات الهيكل أو الأنيميشن، ولا أجزاء morph targets.
3. الخامات حتى 2048 بكسل للضلع الأطول، مع الحفاظ على النسبة وعدم تكبير الصور الصغيرة. خرائط اللون فقط تستخدم WebP بجودة 95؛ خرائط النورمال والبيانات تستخدم WebP lossless **بعد أي تصغير**. إذا لم توفر الصورة الناتجة حجمًا، تبقى الصورة الأصلية. لا نُسقط امتدادًا غير مدعوم بصمت: يرفض هذا النوع برسالة واضحة.
4. ضغط النقل Brotli/gzip بلا فقد إضافي. لا تُرسل المجسمات أو صور الكاميرا لخدمة معالجة خارجية.

التبسيط وتصغير الخامات وضغط اللون عمليات تقريبية، وليست تطابقًا رياضيًا مع الأصل. تُقارن النتيجة بصريًا، خصوصًا الكتابة الدقيقة والتفاصيل عند التكبير. الحجم النهائي يعتمد على الملف؛ هدف 2–5 MB ليس حدًا نضحي بالتفاصيل للوصول إليه.

## قياسات فعلية في الاختبار

| الملف | قبل | GLB الويب | التنزيل مع Brotli | المثلثات |
|---|---:|---:|---:|---:|
| HEAD 12029 الأصلي | 62.7 MiB | 5.69 MiB | 5.61 MiB | 1,500,000 ← 100,000 |
| HEAD 12029 المعد مسبقًا | 11.8 MiB | 6.23 MiB | 6.13 MiB | 75,000 كما هي |
| HEAD 12028 الأزرق | 1.96 MiB | 0.73 MiB | 0.66 MiB | 74,998 كما هي |

قد ينتج الملف الأصلي الكبير نسخة أصغر من ملف سبق تصديره؛ تختلف الرؤوس وخرائط الخامات والتانجنت الموجودة في كل مصدر. استُخدم المصدر نفسه قبل/بعد للمقارنة من الأمام والجانب وبزاوية مائلة، بالإضاءة والكاميرا ونقاط التثبيت نفسها. تطابقت نقاط الملاءمة وبقي التحكم بذراعين. في الموديل الأزرق تحقق الاختبار من بقاء قيم جميع سمات الرؤوس مطابقة على مستوى البت، مع اختلاف الترتيب فقط.

## العزل والحفظ

تعالج مهمة واحدة فقط في عملية Node منفصلة، بحد heap مقداره 512 MiB ووقت 4 دقائق، وتُغلق عند إلغاء رفعها. الذاكرة الأصلية للمكتبات والصور إضافية لهذا الحد؛ حد heap ليس حد RAM كاملًا. تنتهي العملية بعد كل موديل لتُحرَّر ذاكرتها. تحتاج معالجة المصادر الكثيفة إلى ذاكرة أكثر من تقديم الملفات؛ ينصح بخادم ذاكرته 2 GiB على الأقل لهذا المسار.

تُفحص النسخة بعد المعالجة وقبل النقل إلى `uploads`. تحفظ `model` نسخة الويب، و`modelOriginal` الأصل، و`modelBytes` و`modelOriginalBytes` أحجامهما، و`modelOptimization` إصدار المعالجة ونتيجتها. يبقى `sourceSha256` بصمة المصدر، وتبقى بيانات الملاءمة المضمّنة وخرائط البصمات المعروفة محفوظة.

سكربت النسخ الاحتياطي المحدّث يضم الأصل ونسخة الويب وكل صور المنتج، وملفات النقل `.br` و`.gz` إن وُجدت. يمكن تقديم GLB عاديًا عند استعادة نسخة دون ملفات النقل؛ لا تُفقد إمكانية التجربة. الملفات القديمة لا تُحذف تلقائيًا.

## تحديث EC2 مرة واحدة

```bash
cd ~/tryit
git pull --ff-only origin main
sudo install -m 0644 scripts/backup.py /usr/local/lib/tryit-backup.py
sudo systemctl start tryit-backup.service
```

بعد نجاح النسخة الاحتياطية:

```bash
sudo systemctl stop tryit
npm ci --omit=dev
sudo systemctl start tryit
```

إذا فشل تثبيت الاعتمادات، شغّل `sudo systemctl start tryit` لإعادة الخدمة وراجع الخطأ. لا يلزم Blender أو GPU أو اشتراك. تشمل الاعتمادات الجديدة glTF Transform وMeshoptimizer وSharp وDraco decoder، وتُثبّت عبر `npm ci`. لا تتغير كلمة المرور أو إعدادات S3. حد Nginx السابق 220 MiB ووقت الوكيل 600 ثانية كافيان؛ لا يلزم تغييرهما إذا طُبّق تحديث رفع الملفات السابق.

في الإنتاج تبدأ معالجة الموديلات القديمة تلقائيًا، ثم يُستخدم مسار جديد عند تحميل الصفحة التالية. يمكن تعطيل هذه المعالجة عند بدء التشغيل فقط بوضع `AUTO_OPTIMIZE_EXISTING=0` في بيئة الخدمة؛ يظل تحسين الرفع الجديد وزر الإدارة متاحين. لم يُنفّذ نشر EC2 من بيئة التطوير.

## الفحوص القابلة للإعادة

```bash
npm test
npm run test:browser
python3 test/test_backup.py
node scripts/optimization-smoke.mjs
OPTIMIZE_GLB_FIXTURE=/path/to/original.glb node scripts/optimization-smoke.mjs
node scripts/optimization-migration-smoke.mjs
CAMERA_FIXTURE=/path/to/face.y4m HEIC_FIXTURE=/path/to/photo.HEIC UPLOAD_GLB_FIXTURE=/path/to/original.glb node scripts/admin-upload-smoke.mjs
```

تتحقق اختبارات API من الملف الأصلي بايتًا ببايت، وفك Brotli/gzip، وعناوين الكاش، والحفظ الذري، ورفض الملفات غير المدعومة دون نشرها، وعدم إعادة معالجة المنتج المحسّن. يتحقق الاختبار المرئي من فك GLB المحسّن فعليًا عبر مكتبات المتجر ومن عرض ثلاث زوايا، وحدّ اختلاف الصورة، ونقاط التثبيت والأذرع. يستخدم اختبار الإنتاج كتالوجًا مستقلًا تحت `/tmp` ويحاكي تحديث الموديلات الحالية دون تغيير منتجات المالك. يمكن تمرير مساره الناتج إلى `SMOKE_PROJECT_ROOT` عند تشغيل اختبار الهاتف لاختبار الملفات المحسّنة فعليًا. هذه محاكاة Chromium، وليست اختبارًا على كاميرا هاتف مادي.
